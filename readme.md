# 面向 CS / Robotics 研究的 Codex 配置

这套配置来自一名计算机科学与机器人方向的 PhD 学生，日常用于论文复现、实验代码开发和调试。目标是在优先保证代码正确性与研究可复现性的前提下，保持代码干净、简洁，并通过 GPT-6 Sol 与 Luna 的任务分工减少额度消耗。

## 文件说明

- [config.toml](config.toml)：主模型、推理强度、子代理并发及本地工具配置。
- [AGENTS.md](AGENTS.md)：最小修改、研究语义保护、验证和委派规则。
- [agents/](agents/)：各子代理的模型、权限与职责边界。

## 模型与任务分工

| 角色 | 模型 / 推理强度 | 职责 |
| --- | --- | --- |
| 主代理 | GPT-6 Sol / medium，Plan 模式 high | 规划、架构与科学决策、处理歧义、任务委派和最终验收 |
| `scout` | GPT-6 Luna / high | 只读检索代码、配置、文档和日志，返回关键证据 |
| `quick_implementer` | GPT-6 Luna / high | 实现已决定、范围明确的局部修改，执行针对性验证 |
| `system_implementer` | GPT-6 Sol / medium | 实现已批准的跨模块或需要理解子系统的改动 |
| `debugger` | GPT-6 Sol / high | 复现非显然故障，先定位根因；修改代码需主代理明确委派 |
| `reviewer` | GPT-6 Sol / high | 只读审查具体的正确性、回归或研究语义风险 |

未指定角色的子代理默认使用 Sol / medium；手动 `/review` 使用 Sol。Luna 不承担架构、算法或实验方法决策，任务超出边界时停止并交回主代理升级处理。

## 配置思路

- **代码保持精简**：优先复用已有实现和依赖，只做必要的局部修改，避免无关重构、一次性抽象和没有证据支持的防御逻辑。
- **研究语义优先**：复现时保留参考算法、数值行为和相关依赖版本；不擅自改变坐标系、单位、归一化、数据划分、指标、随机种子或实验协议。有实质歧义时先查证或询问。
- **按需委派以节省额度**：简单任务交给 Luna，复杂判断留给 Sol；微小修改由主代理直接完成。默认一个子代理工作，仅对独立调查使用第二个，避免重复探索和重叠修改。
- **验证与风险匹配**：执行最小但足够的测试、构建或烟雾检查，不默认运行全套测试；仅在存在具体未解决风险时增加审查。节省额度不能替代正确性验证，实际节省效果需结合使用情况评估。
- **控制实验成本**：小型定向测试可自动执行；昂贵训练、大规模仿真、多种子实验、参数扫描、大量下载和真实硬件操作需明确授权。

这是个人研究工作流的配置记录。`config.toml` 包含本机 Windows 路径、插件和 MCP 设置，其他人复用时应按自己的环境调整。子代理配置机制可参考 [OpenAI 官方文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。
