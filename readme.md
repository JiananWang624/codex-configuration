# 面向 CS / Robotics 研究的 Codex 配置

这套配置来自一名计算机科学与机器人方向的 PhD 学生，日常用于论文复现、实验代码开发和调试。目标是在优先保证代码正确性与研究可复现性的前提下，保持代码干净、简洁，并通过 GPT-6.1 Sol 与 GPT-6 Luna 的任务分工减少额度消耗。

## 文件说明

- [config.toml](config.toml)：主模型、推理强度、子代理并发及通用偏好设置。
- [AGENTS.md](AGENTS.md)：最小修改、研究语义保护、验证和委派规则。
- [agents/](agents/)：各子代理的模型、权限与职责边界。

## 模型与任务分工

| 角色 | 模型 / 推理强度 | 职责 |
| --- | --- | --- |
| 主代理 | GPT-6.1 Sol / medium，Plan 模式 high | 规划、架构与科学决策、处理歧义、任务委派和最终验收 |
| `scout` | GPT-6 Luna / high | 只读检索代码、配置、文档和日志，返回关键证据 |
| `quick_implementer` | GPT-6 Luna / high | 实现已决定、范围明确的局部修改，执行针对性验证 |
| `system_implementer` | GPT-6.1 Sol / medium | 按明确实现契约完成方案已确定、工作量较大且适合隔离实施上下文的任务，包括模块交互、集成路径和较大量的验证工作；发现证据与契约冲突时交回主代理 |
| `debugger` | GPT-6.1 Sol / high | 复现非显然故障，先定位根因；修改代码需主代理明确委派 |
| `reviewer` | GPT-6.1 Sol / high | 只读审查具体的正确性、回归或研究语义风险 |

未指定角色的子代理默认使用 GPT-6.1 Sol / medium；手动 `/review` 使用 GPT-6.1 Sol。配置显式启用 Multi-Agent V2，并发上限保持为 2。Luna 不承担架构、算法或实验方法决策，任务超出边界时停止并交回主代理，由主代理决定直接处理或委派给 `system_implementer`。

## 配置思路

- **代码保持精简**：优先复用已有实现和依赖，只做必要的局部修改，避免无关重构、一次性抽象和没有证据支持的防御逻辑。
- **研究语义优先**：复现时保留参考算法、数值行为和相关依赖版本；不擅自改变坐标系、单位、归一化、数据划分、指标、随机种子或实验协议。有实质歧义时先查证或询问。
- **按需委派以节省额度**：仅在上下文隔离、专门分工或独立工作带来的收益足以抵消额外成本时委派。明确的局部任务交给 Luna，较大的已批准实现可交给 `system_implementer`；与未解决科研或架构决策紧密耦合的实现留在主代理。通常只启用一个子代理，仅对真正独立的工作使用第二个，最多两个，避免重叠修改。
- **减少上下文与重复创建**：委派任务包含目标、已决定的约束、相关文件、验收标准和必要验证。创建命名子代理时显式设置 `fork_turns`，默认使用 `"none"`；需要近期背景时继承少量轮次，仅在必要时使用 `"all"`。相关后续任务优先通过 `followup_task` 复用已有代理，子代理未经主代理授权不得继续创建子代理。
- **验证与风险匹配**：执行最小但足够的测试、构建或烟雾检查，不默认运行全套测试；仅在存在具体未解决风险时增加审查。节省额度不能替代正确性验证，实际节省效果需结合使用情况评估。
- **控制实验成本**：小型定向测试可自动执行；昂贵训练、大规模仿真、多种子实验、参数扫描、大量下载和真实硬件操作需明确授权。

这是一套可供参考的研究工作流通用配置。`config.toml` 已移除个人 MCP、本机绝对路径，以及依赖本机安装位置的插件市场和插件配置。需要使用 MCP 或插件时，请在自己的环境中单独配置；`[windows]` 为 Windows 专用设置，其他系统可省略。子代理配置机制可参考 [OpenAI 官方文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。
